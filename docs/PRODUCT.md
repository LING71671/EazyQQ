# EazyQQ 产品规格

<!-- impeccable:product-schema 1 -->

本文描述 0.5.0 已实现的能力和验收边界。接口细节以 [接口文档](API_SPECIFICATION.md) 和生成的 CLI schema 为准。

## 使用者与平台

面向个人 QQ 用户、群运营者、中国开发者及通过 CLI/MCP 接入的智能体。运行平台为 Windows x64；需要官方 QQNT，协议层使用 NapCat / OneBot 11。桌面端使用 Tauri/WebView2，后台能力由共享 Rust 服务提供。

## 账号生命周期

1. 登记 QQ 号，分配独立 HTTP、WebSocket 和 WebUI 端口；登记不等于启动。
2. 支持批量启动、登录、停止及逐账号结果查看。
3. 优先复用已验证的目标会话；快速凭据过期时获取目标二维码。
4. 等待目标身份确认，之后提交当前账号切换并重建桌面上下文。
5. 忘记账号只移除登记；账号目录、数据库和文件保留。

切换不是退出其他账号。已有外部 QQ 会话保持外部管理状态，不能因为端口不方便或诊断异常而被强制结束。各账号的数据、模型会话、浏览器缓存和工作租约独立。

## 消息处理

| 模式 | 行为 |
| --- | --- |
| `auto_reply` | 符合触发条件与冷却规则后生成并发送回复 |
| `copilot` | 生成草稿，人工审核后发送 |
| `summary_only` | 记录允许处理的消息，用于简报 |
| `ignore` | 跳过 AI；若明确开启总结白名单，可保留总结所需消息 |

触发条件包括 @我、关键词和全部消息。默认不处理未加入规则的对象。消息、规则、草稿、未读和简报按账号隔离，外来账号的 WebSocket 事件被丢弃。

## 简报与文件

支持滑动时间窗口、按群设置的总结白名单、定时调度、手动总结、流式展示和历史查询。群文件支持索引、受大小上限约束的下载和文档提取/综述。界面速率属于文本输出估算，不能当成服务端准确计费 Token 数；原生 OpenCode 也可能按文本段输出。

## 模型

免费 OpenCode 通过本机原生运行时调用；不伪造客户端身份，也不把普通云服务密钥自动当成 OpenCode 凭据。自定义或本地兼容模型使用 HTTP/SSE。模型名称、可用范围和免费状态来自当前运行时/目录；显式推理测试验证当前是否可调用。

## 健康与恢复

八个环节：WebUI、QQ 身份、OneBot HTTP、WebSocket、SQLite、模型、调度和前端。状态分为正常、未知、失败。待扫码、未验证推理、仅有开放端口不能当成成功。

一键修复按故障处理：缺失服务可启动；登录与模型问题给出对应操作；WebSocket 工作进程自行重连。正常会话、外部进程和已运行的协议实例不会被统一重启。周期检查不发起模型推理。

## CLI 与 MCP

CLI 覆盖桌面后端操作，支持账号上下文、JSON 输出和批量任务。窗口操作需要已运行的桌面。MCP 使用 stdio JSON-RPC，实际工具及字段通过 `tools/list` 返回。日志不会污染 JSON stdout。

## 本地与外部数据

本地数据位于机器/账号目录。云模型会接收用户允许处理的会话内容，因此“本地保存”不代表“从不发送到云端”。发布包排除个人配置、凭据、缓存、SQLite 和运行日志。QQ、OpenCode、网络及远端服务仍是外部依赖，不能承诺永不失效或永远免扫码。
