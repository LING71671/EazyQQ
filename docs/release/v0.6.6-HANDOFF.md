## 发布执行顺序

### 1. 解除资源版本耦合并补 CI（约 10–20 分钟）

先处理发布前的明确耦合：`scripts/ai/sync-native-faces.mjs` 的 `SOURCE_PATH` 固定在 `src-tauri/resources/protocol/0.6.5/...`，经典来源校验要求既有资源及精确 SHA。不能只改应用版本后依赖 CI 碰巧存在旧目录，也不能把新的 NapCat 资源当作相同哈希来源。

推荐将旧经典映射或必要的固定公开来源数据做成独立、受 SHA 固定的本地快照，与已有 `scripts/ai/data/qface-native-faces.c96fa14.json` 一样可离线重现；保留 407 项合并规则和真实 APNG 来源，不引入私人导出作为公共数据源。测试应在没有开发机缓存/旧版本资源目录时仍能运行。

把 `node --test scripts/ai/*.test.mjs` 与目录一致性检查加入开发和发布 CI。当前 CI 的 `pnpm test` 仅执行 Vitest，不会自动覆盖这些 Node 分析器/编译器测试。发布流程会下载最新 NapCat，须核对它与固定表情来源的独立边界，不静默放宽来源验证。

### 2. 统一版本与发布说明（约 5–10 分钟）

统一 `package.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` 中本包版本、`src-tauri/tauri.conf.json`，运行 `pnpm contracts:write` 与 `pnpm version:check`。同步 README、CHANGELOG、产品、接口和 `llms` 文档；新增 `docs/release/v0.6.6.md`。

发布说明围绕可观察行为，说明 V2 需新程序、旧包兼容、私人包不会随安装包提供；当前旧安装包没有这些增量。保留已保存中转站模型/端点/Key，不探测用户模型的多模态能力，不默认启用接管规则。模型预设不等于实时免费额度或全部模型可用。

### 3. 构建与打包（缓存命中约 6–15 分钟）

按 `RELEASING.md` 完成必要门禁。避免重复已完成的探索性或真实聊天测试；版本/资源/CI 改变后，以最终发布修订和真实产物为验收对象。

```powershell
pnpm presentation:check
pnpm typecheck
pnpm test
node --test scripts/ai/*.test.mjs
pnpm test:release
pnpm test:rust
pnpm contracts:check
pnpm tauri:build
$env:EAZYQQ_TEST_CLI = (Resolve-Path src-tauri/target/release/eazyqq_cli.exe).Path
$env:EAZYQQ_TEST_GUI = (Resolve-Path src-tauri/target/release/eazyqq.exe).Path
pnpm test:smoke
pnpm test:native
pnpm release:package
git diff --check
```

如配置 `CARGO_TARGET_DIR`，上面两个环境变量指向实际目标目录。正式构建不能加 `--no-bundle`；打包前必须存在 `release/bundle/nsis/EazyQQ_0.6.6_x64-setup.exe`。安装验证使用既有 `scripts/validation/install_bundle.ps1` 与隔离夹具，不删除、迁移用户安装目录或重启健康 QQ。联网表情预览已有证据，可按需启用 `EAZYQQ_TEST_FACE_NETWORK=1`；默认原生测试封锁表情图以验证离线回退。

检查 `output/release/0.6.6/`：安装包、CLI ZIP、两份 CLI 文件、`latest.json`、`SHA256SUMS.txt`。核验二进制版本、清单 `sourceRevision`、大小及逐文件 SHA256，确认没有私人风格包、安装索引、聊天记录、账号配置、日志或 SQLite。生成契约和资源必须属于最终修订，不能把旧 0.6.5 安装包改名当作 0.6.6。

### 4. 提交并运行 GitHub 发布流程（约 10–20 分钟，视 CI）

补齐中文开发记录，提交版本、CI 和发布文档。确认用户本次执行指令包含发布后，使用未占用的新标签触发 `.github/workflows/release.yml`；不要直接绕过既有 publisher 上传资产，不强制移动公开标签。

```powershell
git push origin main
git tag -a v0.6.6 -m "Release 0.6.6"
git push origin v0.6.6
gh run list --workflow release.yml
```

标签必须指向已完成验收的最终提交。workflow 会校验公开 Release 不可覆盖，运行构建/安装/原生门禁并由 `scripts/release/publish.mjs` 逐写入边界检查草稿状态；出现拒绝时记录实际原因，不覆盖公开资产。

### 5. 发布后核验与交付（约 5 分钟）

检查正确标签的 Actions 结果、Release 状态、资产列表和来源修订；从公开下载地址取 CLI ZIP 到独立隔离目录，核对 SHA256 和 `version --json`。报告 Release 链接、提交、版本、真实验证结果及未完成项。只有完成这些步骤才称“已发布”。
