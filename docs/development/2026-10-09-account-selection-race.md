# 账号选择被旧状态响应回滚的竞态

## 证据与溯源

候选 0.5.4 的发布作业 [37940700059](https://github.com/LING71671/EazyQQ/actions/runs/37940700059) 在原生账号往返失败，未创建 Release 或公开资产。构建、安装、映射 DLL 下重装、数据保留、CLI 冒烟和协议恢复已通过，失败位置是 `native_profiles.py` 返回 10001 的阶段。

日志顺序为 22:08:47.047 选择 10001，22:08:47.062 又选择 10002，随后新上下文启动为 10002，测试等待 10001 超时。不是无证据的 WebView2 或网络推断；旧上下文的 `get_protocol_status` 在显式选择后返回原账号证据，并调用 `reconcile_account`，将共享选择状态改回旧账号。这个竞态也解释了真实用户快速切换时结果不稳定的风险。

## 修复决策

显式 GUI 选择通过 `select_for_restart` 保存目标，但旧进程的 active 身份保持不变，直至新进程重建固定的数据库、模型、工作进程与路径。该操作与身份观察使用同一个进程 mutex；持久化使用已有跨进程 bootstrap 文件锁。原子提交失败不改内存身份。

已绑定客户端的状态观察只报告身份，绝不提交选择。首次未绑定客户端可通过 `adopt_observed` 提交已验证身份，但只有当前内存和 bootstrap 均未绑定时成立；晚到的首次观察不能覆盖 GUI 或另一个 CLI 已保存的目标。`update_bootstrap_if` 在条件不成立时不重写文件。

CLI 的显式 `adopt` 仍在本次命令中提交目标，GUI 和 CLI 的参数/DTO 不变。身份验证、目标二维码、消息授权、原有 QQ 所有权和未实施的登录态/内存策略保持。

## 回归与边界

新增 Rust 回归验证首次身份确认、GUI 目标保存时旧进程身份不变、旧绑定响应与未绑定晚到响应不能回滚选择，以及其他进程已保存目标时保持 bootstrap 原字节。完整 Rust 120 项库测试和 2 项 CLI 测试通过。

原生验收在切换前并发发起旧账号状态请求，模拟服务先扣留响应，确认新目标已保存后才释放；继续验证账号往返与 localStorage 隔离，未延长等待或删掉断言。`.test-runtime/selection-race-native-final.log` 已通过，`delayedStatusSelectionPreserved=true`，其余账号往返、浏览器缓存、窗口与手册断言均保留并通过。

首轮本机 GUI 复验错误地使用直接 Cargo 生成 GUI，未通过 Tauri 的生产协议构建，导致首屏调试入口无法匹配；不是账号往返验证通过。已改回 `pnpm tauri:build`，记录实际构建及复验结果。未操作用户 QQ 或修改本机驱动/注册表。

候选 v0.5.4 标签保持原来源，不强制覆盖；它没有公开 Release。合并修复后使用新版本 0.5.5 进行完整发布验收，以免未授权改动远端标签。0.5.5 尚未构建、发布或安装时不得写成完成。
