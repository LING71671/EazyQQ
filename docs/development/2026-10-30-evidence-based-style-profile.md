# 基于证据的聊天风格画像

## 起始状态与原因

用户指出上一轮风格包过于简陋且不准确，明确要求专业分析。起点为上一轮未提交的上下文、多模态和风格包增量，已有修改全部保留。旧包以总体消息中位数、几个比率、固定口语语气和保守短反应白名单生成，不足以代表条件化表达。

复查发现旧分析将导出的表情名称计入文字长度，按消息而非完整回合估计表达节奏，使用导出顺序判断连发，没有独立留出验证；大量会话混合后缺少集中度与时间变化审查。旧程序表情目录只有经典子集，会遗漏常用的新编号。旧包的可导入验证只能证明格式与存储，不能证明风格准确。

## 决策与兼容边界

新增可重复的本地语料分析，按明确作者映射、会话与消息复合编号、时间排序、媒体分型和完整回合形成证据。分离训练与按时间留出的回合，报告内容重复剔除、样本集中度、跨会话平均和最近时期差异；语义标签如由规则分类，明确标为近似而非人工真值。

风格包 V2 在兼容原表达枚举的基础上增加分析方法、样本范围、量化分布、条件模式、匿名证据引用和经过检查的情境示例。统计不能成为每次回复的字数或句数配额，过去的示例不能作为当前本人事实。V1 继续可读；本机账号索引与可分享包仍分开，V2 不能带自由系统提示、工具权限或身份覆盖。

个人原文、候选片段、画像、完整报告和生成过程仅在 Git 忽略目录；公共实现、文档和测试不包含真实联系人、个人短语、源目录或私人统计。未调用用户配置的真实模型，未向 QQ 发送消息，未安装或启用真实账号规则。

真实 Tauri/WebView2 验收通过（`.test-runtime/native-profiles-aig_lhc3`）：合成 V2 可从界面导入，实际捕获请求含条件模式和匿名示例引用，停用/账号切换保持隔离。用户随后要求动态外观检查，增加显式联网素材验收（`.test-runtime/native-profiles-_s3ty6rv`）：324/427 均解码为 128×128 图像，各捕获 18 个不同的界面画面。这里证明的是本程序动态预览；不把模拟协议回执当作真实 QQ 投递证据。用户之后要求停止额外验证并尽快提交，未发送真实 QQ 消息。
