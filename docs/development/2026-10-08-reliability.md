# 登录可靠性与多账号开发记录

日期：2026-10-08。后续接续入口：[0.5.0 发布记录](2026-10-08-release-0.5.0.md)。本文保留 0.3.x 修复阶段的原因与证据；当前目录和契约以架构与接口文档为准。

## 起始状态与目标

工作区开始时已有未提交的界面、认证、模型、诊断、进程、存储及更新修改，全部保留，未重置仓库。用户要求修复概率性快速登录失败、扫码后诊断仍未登录、免费 OpenCode 调用失败、硬编码版本、不合理自愈及误伤 QQ，并增加多账号、批量管理和 CLI 覆盖。

## 已确认原因与修复

| 原因 | 修复与依据 |
| --- | --- |
| 快速登录重复停止协议，身份未确认先写入目标选择 | 共用账号操作服务；确认预期身份后提交选择，失败保留当前上下文 |
| GUI 与监控使用不同状态字段，失败 OneBot 响应仍被当作成功 | `LoginEvidence` 验证响应封装、非零身份和账号匹配；支持 WebUI 两种字段，正确 OneBot 证据优先 |
| 免费模型直接走公开兼容 HTTP 端点 | 使用本机原生 OpenCode 运行时、账号私有会话及非交互工具权限 |
| 版本兜底常量与错误升级排序 | 构建/运行时 metadata，SemVer 包含预发布信息，不提供降级 |
| 安装/恢复按 QQ.exe 名清理 | 随机 Windows Job 所有权；只终止本次创建的进程树，外部会话保留 |
| 多账号共用 WebUI 端口及可写协议文件 | 三端口分配，私有 config/cache/log/SQLite，只有不可变资源可共享 |
| 重叠轮询和迟到二维码覆盖新状态 | 串行轮询、操作代际与取消保护；目标扫码仅接受指定身份 |
| CLI 布尔参数吞掉子命令，JSON stdout 混入日志 | 修正参数解析与日志路由，生成并验证接口 schema |

## 架构决策

登录探测只读。桌面切换重建应用上下文，数据库、AI、下载和工作流句柄不在原地改绑。每个账号独立消息与调度工作进程，系统文件租约避免 GUI/CLI 重复消费。冷却键包含账号和会话类型。

持久 JSON 使用系统锁和原子替换；损坏登记不静默覆盖。恢复按故障环节决定动作，认证成功、已运行和外部管理的进程被保留。周期健康检查不生成模型请求。

升级先暂存归档，检查路径和符号链接，保留个人配置与回滚备份，并通过维护锁协调停机。分层子目录保留公共模块导出，降低入口适配层与具体文件布局的耦合。

## 实机发现

旧登记将两个账号分配到同一 HTTP/WS 端口。Windows 仅凭绑定成功也无法证明 WebUI 端口空闲，因此增加连接探测。只允许未生成私有配置的新登记刷新过期预留。

隔离协议实例成功连接已安装 QQNT；QQ 返回目标快速凭据已失效。用户完成手机扫码后，OneBot 返回目标身份，链路诊断与 CLI 健康同步确认已登录。凭据失效没有触发原账号退出或反复重启。

协议资源中发现 SQLite 缓存可能被硬链接，补充数据库、缓存、加载器、修补清单和进程收据排除。只停止新建的受管理测试进程后处理其缓存链接，原有文件保留。

原生桌面完成目标账号与已认证外部端点的往返切换，每个替换进程打开对应数据库。两个人工原有 QQ 主进程仍在运行；用户日常账号没有被选择、切换或退出。进程存活只能证明未被终止，不能替代每个外部账号的认证证据。

对健康目标执行修复返回 `action=none`、`attempted=false`、`ok=true`。原生 OpenCode big-pickle 返回 OK，最后一次账户隔离推理耗时 33,276 ms；未伪造客户端标识。

## 监督进程寿命

CLI 调用宿主可能在命令结束后终止后代进程，造成刚启动就消失。监督进程通过 Windows 进程服务边界启动并持有独立 Job；使用内容散列命名的二进制副本，避免锁定构建/安装产物。

WMI 的 `ShowWindow` 使用 Int32 会返回类型不匹配；明确使用 UInt16 后创建成功。真实隔离协议进程跨 CLI 调用保持运行并完成手机确认登录。收据 PID 仅提供信息，不允许陈旧 PID 回退清理。

## 验收中追加的修复

CLI 健康报告原来显示固定端口，并把字符串 QQ 号显示为零；现在复用身份证据与实际端点。SQLite 错误不再转为成功的零规则结果。

最大化还原原来误用 unminimize，现改为 unmaximize。启动看门狗原来用窗口可见性判断 JavaScript 是否启动，现依据真实前端 IPC，隐藏健康窗口不会触发关闭沙箱或重启。兼容重启增加单实例交接标记。

来源数据库的 WAL/SHM 曾可能移入已有目标数据库；现在已有目标数据库时保留整个来源数据库族，回归测试证明目标不变、来源 WAL 保留。继承的单元测试曾使用真实路径；现强制每进程测试根目录并为账号状态测试加锁。

## 浏览器隔离补验闭环

绝对路径写进 Tauri `WindowConfig.dataDirectory` 会被忽略并回退为共享目录；最终改用 `WebviewWindowBuilder.data_directory` 创建真实窗口。

首次再次启动真实测试桌面被自动审批拒绝，仅返回 `blocked by policy`；用户表示不能且不愿手动操作，因此当时如实记为未验。随后发布准备使用全新的模拟协议和独立目录，无真实 QQ 启动器、不需要手机，以真实 Tauri 验证两个账号 localStorage 分离及往返恢复，验收成功。旧“缓存未验”状态已关闭，不能继续引用为当前缺口。

## 阶段证据与边界

0.3.x 修复实现已通过 94 项库测试、2 项 CLI 测试、10 项前端测试和 24 项 CLI 冒烟案例；发布版 CLI 也通过同一套冒烟。浏览器模拟验收覆盖批量登记、准确目标、凭据过期扫码及目标确认后切换。

完整操作映射包含 53 个桌面入口和 58 个 CLI 命令；生成矩阵检查不能代替每项实际行为验证。协议流模拟覆盖双账号事件、外来身份拒绝和重复消费保护。原生缓存补验使用模拟协议验证真实桌面边界。

旧安装包成功生成，包含一个 CLI 项且未包含个人资源。测试 GUI 和新建协议实例已关闭，原有 QQ 会话保留，隔离登记自启恢复为关闭。没有发送真实消息、启用真实自动回复、执行安装或升级，也没有按 QQ 进程名终止进程。

0.5.0 的最终验收、发布资产和 Git 状态详见后续发布记录。历史实际版本与包大小属于当时构建，不应当成当前运行时版本兜底。
