## 决策与边界

1. 人工发送在完整前后端链路保留会话类型；持久化或发送成功后才更新成功状态，失败保留编辑内容并显示原因。
2. 更新沿随机操作编号持久追踪检查、下载、校验、交接和核心部署；安装退出 0 与实际新版本启动分别取证，旧回执兼容且查询只读。
3. 免费检测在固定账号与请求编号下取消，只回收本次创建的子进程和有所有权标记的私有临时目录；本次部分证据与历史完整证据分开。
4. GUI、CLI 和 MCP 复用链路三态与恢复建议；被动检查不推理，不将未观察到的其他进程组件当作失败，不统一重启协议。
5. 功能增长按用户任务、现有服务复用、投入与成功指标排序；另行记录建议，避免将底层门禁本身当作产品增长。

## 原生验收串行重验（2026-10-29）

夹具修复后按用户指令串行重跑原生验收，第一轮暴露两处问题并当轮修复：

1. 构建工具链：`build-opencode-fixture.ps1` 经 `Enable-MsvcEnvironment` 调用 `vcvars64.bat`，后者依赖 reg.exe 查询 Windows SDK；宿主安全策略拦截 reg.exe 时 INCLUDE/LIB 静默丢失 SDK 段，cl 在 stdio.h 编译失败、在 kernel32.lib 链接失败。修复 `scripts/toolchain/msvc.ps1`：导入 vcvars 后检测 INCLUDE 缺 ucrt 时按磁盘目录补齐 SDK 头与库路径，不触碰注册表，正常环境零影响。
2. OneBot 错误文本：`validate_response` 只读响应 `message` 字段，而 OneBot 11 标准错误文本字段为 `wording`（模拟协议与真实 NapCat 一致），真实失败原因被替换为 "Invalid response"。该缺陷同样影响真实 NapCat 的失败显示，属 0.6.5 可靠性范围；修复 `transport/onebot.rs` 以 `wording` 优先、`message` 兜底。

证据：重建 release 二进制后 `pnpm test:native` 通过（Python 退出码 0），验收 JSON 报告 11 项全部为真：登录首屏视口、免费模型发现、模型健康同步、免 Key 通道隔离、更新历史证据、账号往返、延迟状态选择保留、私有配置目录、最大化往返、手动快捷键、未触碰真实 QQ。reliability 段确认模拟 OneBot 拒绝（retcode 1200）以「模拟消息发送失败」渲染为可见错误、消息草稿保留、设置写入被拒时不误报成功；free detection 段确认慢启动夹具的停止与本次子进程回收。

本机 `pnpm tauri:build` 产物完整（eazyqq.exe、eazyqq_cli.exe、NSIS 安装包均生成，版本 0.6.5），但进程以非零码结束：收尾阶段宿主安全策略拦截 vcvars 内部的 reg.exe 调用。产物已被上述原生验收实际使用验证；CI 环境无此限制，release.yml 将完整重跑构建。
