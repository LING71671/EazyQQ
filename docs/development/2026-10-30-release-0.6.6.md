## 发布前耦合与决策

`scripts/ai/sync-native-faces.mjs` 原本从 `src-tauri/resources/protocol/0.6.5/static/assets/qface-BZLvZXJ8.js` 读取 275 项经典映射并校验该文件 SHA256。`scripts/sync-napcat-resources.mjs` 在每次 `prepare:resources` 时会把非当前版本的协议目录移入 `.test-runtime/resource-backups/`，因此版本号改为 0.6.6 后该源文件不再存在；CI 的 release 流程也在 `pnpm test` 之前完成资源准备，同样没有旧目录。原测试只被 `pnpm test`（Vitest）覆盖不到，属于必然失败但无人发现的路径。

决策：把经典映射固化为本地快照 `scripts/ai/data/qface-classic-BZLvZXJ8.json`，与既有公开索引快照 `qface-native-faces.c96fa14.json` 同构，并在文件内记录原始来源路径与 SHA256。`pinnedClassicFaces` 校验文件自身 SHA256（生成时固定为 `2f02df68…`）、`schemaVersion`、`upstream.source`、`upstream.sha256` 与逐条记录的编号、名称和预览 URL 形状；`parseNativeFaces` 保留为解析器与回归入口，用于未来重新生成快照时校验来源，不再在构建路径上读取版本目录。407 项合并规则、公开索引的 commit/SHA 固定、真实 APNG/GIF 预览地址与 `face{id}` 发送方式均未改变，也未引入任何私人导出。

验证方式：临时把 `src-tauri/resources/protocol/0.6.5` 移出工作区后重跑 `node --test scripts/ai/*.test.mjs` 与 `--check`，31 项测试与 407 项目录检查仍通过，再恢复目录。

CI 门禁：`.github/workflows/ci.yml` 与 `.github/workflows/release.yml` 在 `pnpm test` 之后增加 `node --test scripts/ai/*.test.mjs` 与 `node scripts/ai/sync-native-faces.mjs --check`，使 Node 分析器/编译器测试与表情目录一致性成为开发和发布门禁，不依赖开发机缓存。

## 构建环境修复

本机 `pnpm test:rust` 首轮链接失败：`LNK1158: 无法运行 mt.exe`。根因是宿主安全策略阻止 `scripts/toolchain/msvc.ps1` 调用的 `vcvars64.bat` 内部 `reg.exe`，SDK 的 `INCLUDE`/`LIB` 已由既有回退补齐，但 `mt.exe` 所在的 `Windows Kits/10/bin/<版本>/x64` 没有进入 `PATH`。修复：在 `mt.exe` 不可见时把最新 SDK bin 目录加入 `PATH`，不修改注册表、不改变产品构建参数；CI 的 vcvars 正常路径不受影响。修复后同一命令 213 项库测试与 4 项 CLI 测试通过。

## 首次发布失败与驱动修复

标签 `v0.6.6` 推送后，工作流 40985856212 依次通过类型、契约、AI 分析器测试、Rust 回归、构建、安装包验证、CLI 与原生验收、打包，最后停在 `Publish release after all checks pass`，日志只有 `Release draft disappeared; publication stopped`，退出码 1。此时仓库确实存在零资产的草稿 Release（id 428567757）。

根因：驱动在创建草稿后立即读取 `/releases/tags/<tag>`，该端点对草稿固定返回 404，只能回落到 `?per_page=100` 的列表；列表由 CDN 缓存，刚创建的草稿在下一次读取中仍可能缺失，单次查询即被判定为“草稿消失”，与真实状态不符。

修复限于发布驱动：读取列表改为有限次退避重试；创建时若返回“同名发布已存在”而随后可见草稿，则继续而非中止；草稿始终不出现时仍拒绝上传，不放宽“不存在不能当作存在”的边界。新增三项回归覆盖延迟可见、始终不可见和创建冲突三条路径，`publish.test.mjs` 由 8 项增至 11 项。修复提交 `710ed34` 只进入 `main`，应用仍由标签 `0a67f7c` 构建，驱动按工作流来源加载，符合既有边界。

## 公开结果

`workflow_dispatch` 以 `v0.6.6` 参数重跑（run 41008159457），全部步骤通过并建立公开 Release：<https://github.com/LING71671/EazyQQ/releases/tag/v0.6.6>，非草稿、非预发布，`publishedAt` 为 2026-10-30T05:38:49Z。六个资产为安装包（33,795,524 字节）、CLI ZIP（54,084,176 字节）、`eazyqq_cli.exe` 与 `ezq.exe`（18,845,696 字节，散列相同）、`latest.json` 与 `SHA256SUMS.txt`；公开 `latest.json` 的 `sourceRevision` 为 `0a67f7c`。

公开资产尺寸大于本机构建，因为 CI 在构建前下载官方最新 NapCat 资源，本地仅使用仓库内既有的 `napcat/` 副本；两者的差异只来自协议运行时来源，应用版本与提交一致。

独立目录复验：从公开地址下载 `latest.json` 与 CLI ZIP，ZIP 的 SHA256 `42b8e7e9…` 与清单一致，823 个条目中不含风格包、数据库、日志、账号目录或缓存；解压后 `bin/eazyqq_cli.exe version --json` 返回 `{"name":"eazyqq_cli","version":"0.6.6"}`，字节数 18,845,696 与清单一致。安装包的公开 `Content-Length` 与清单相同。
