# 0.5.1 启动与更新开发记录

日期：2026-10-09。起始状态：0.5.0 已公开且通过当时的云端门禁，用户下载后在 QQ 9.9.23-42430 上发现加载器缺失错误，要求完善主程序与核心组件更新。

## 诊断与未完成边界

此前原生验收使用模拟协议，没有覆盖真实 QQ 对入口的解析。第一轮绝对路径改动和 path.resolve 回归不足；[Electron 源码](https://github.com/electron/electron/blob/main/lib/browser/init.ts) 使用 path.join。第二轮改为相对入口与同盘目录桥接，直接启动与监督路径的结果仍不一致，不能当作完成。测试误弹到用户桌面，已停止相关受验证 Job；原有 QQ 主进程保留。隐藏桌面没有可靠隔离子窗口，后续真实 QQ 验证转到云端。

发布协议目录的 package.json 声明 type=module，旧测试却写成 commonjs，掩盖格式边界。入口改为显式 loadNapCat.cjs，测试保留真实 type=module；[Node 文档](https://nodejs.org/api/packages.html#packagejson-and-file-extensions) 保证 .cjs 使用 CommonJS。真实启动仍须通过云端，不能用单元回归替代。

## 更新实现与兼容

infra/updates 分离发布选择、流式下载、安装交接与核心部署。主程序精确选择安装包，稳定 SemVer 排序，读取官方 digest 或对应校验和，检查大小和 PE 内容后才安装。暂存使用用户可写路径。安装助手通过 WMI 脱离调用终端寿命，等待调用者退出后再次校验并安装，成功重开，失败保留日志并尝试打开原程序。助手不结束 QQ。

核心只选官方 NapCat.Shell.zip，检查来源、大小与散列；存活会话阻止覆盖，保留私有配置及备份。离线版本读取共享安装资源，完成后重新探测；未知版本不能冒充最新。主程序和核心更新共享跨进程租约。旧客户端按第一个 exe 选择，发布流程先上传安装包以兼容。

桌面使用两个独立更新组件、请求守卫和进度订阅。检查失败清除旧结果，重复点击不重复安装，卸载后释放订阅；任务相互禁用。CLI 和 MCP 继续复用服务，JSON stdout 不混入进度日志。

## 原生安装交接补验

PowerShell 文件中转在 WMI 场景没有执行，原无窗口交接回归明确失败；同一脚本直接执行成功，因此没有把下载完成当作安装完成。最终改为从当前二进制复制内容散列命名的原生助手，两个发布二进制在初始化 GUI/CLI 前进入内部助手模式。助手等待本次进程退出，再验证包的大小与 SHA256、启动 NSIS、处理失败日志及重开，保留 EAZYQQ_ROOT。原生测试用无窗口安装器替身验证退出后执行、中文路径和 /P /R 参数，108 项 Rust 检查通过。

第一轮云端真实 QQ 已启动受管理 WebUI，失败为二维码仍在生成，验证驱动增加只读就绪等待。它没有刷新二维码或触发第二次快速登录。最终云端结果完成后补充。

## 真实旧 QQ 验收

[云端运行 37889026746](https://github.com/LING71671/EazyQQ/actions/runs/37889026746) 成功：QQ 9.9.23-42430 真实启动，入口为私有相对 .cjs，WebUI 监听 PID 属于本次 Job，二维码可读取；未扫码登录，最后定向停止本次 Job。该流程使用与最终版本相同的协议和更新服务源码，后续只增加文档与安装包验收脚本。

最终原生助手不再执行 PowerShell 文件：助手由当前二进制复制并按内容散列命名，WMI 仅负责启动原生进程，UTF-8 JSON 由 Rust 解析。原生进程等待调用者退出后复验并启动安装器，失败写日志；两种入口均在业务初始化前识别内部助手模式。无窗口替身已验证实际执行和中文路径，未安装或打开用户程序。
