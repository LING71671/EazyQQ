# 消息归属、多模态与本地风格包

## 起始状态与授权

起点 `f923b3f`，工作区干净。0.6.5 已由其他开发过程发布，本轮在当前源码上继续开发，不覆盖公开版本、标签或发布资产。用户截图暴露号主历史转发被归给对方，随后生成固定道歉和无依据内容；用户要求修复消息身份、图片文件实际传递、自然表达及 QQ 原生表情。

用户进一步明确授权从指定本地聊天记录提炼本人风格，随后要求改为独立风格包以保护开源隐私；再要求降低 OpenCode 推荐顺序，加入 DeepSeek 官方、AMD、NVIDIA 预设。不验证用户所用模型是否支持多模态，不调用真实模型，不发送真实 QQ 消息，不启用或扩大自动回复规则。

## 根因与决策

1. 历史消息使用每条 `self_id` 判断方向，协议历史缺该字段时号主被算作对方；持久化冲突更新也不修正方向。改用服务固定的账号核验发送者，重同步可修正已有行，保留 AI 发送回执。
2. 上下文只剩 `role/content`，群成员、引用/转发作者和消息 ID 丢失；当前来信又重复加入。统一按稳定消息编号、固定账号/目标类型/目标构造来源信封，当前输入按 ID 排除，外层发送者与转发内声明作者分开。
3. 数据库和界面按相同文本、同方向、60 秒去重，错误删除不同成员的相同短句。保留真实消息 ID，读取不再删除消息。
4. 模型请求将图片、文件、转发都当字符串。新增真实 `image_url` 内容、受限文档正文提取、引用/转发解析与未读取状态；不能用材料名称或未解析 ID 作为已读正文。
5. 原人设泛化为亲切高效助理，重生成强加幽默。统一聊天提示规则，优先回应最后具体来话、短句、少套话；表达风格以独立本地包加载，不编造号主经历、关系或已执行动作。

## 实现边界

`message_sources` 是消息 ID 对应的原始来源侧表，保留当前账号私有数据库，现有公开消息 DTO 不加原始协议负担。新来源含作用域与原始段，读引用仍须证明同账号、同会话；转发节点作者仅是来源声明。旧数据缺来源时保留未知，不能通过昵称认证身份。GUI 构思携带具体来源 ID，草稿重生成也复用来源和历史。

回复准备前按固定会话补取最多 100 条漫游历史，异步同步预算 2.5 秒，读取失败或超时保留已核验缓存；不要求先打开聊天窗口。生成的 OneBot 配置开启 `reportSelfMessage`，不为应用配置重启健康 QQ。自动回复推理前确认当前消息仍有效，发送前再同步历史并重查规则与稳定消息 ID 快照；新来信、号主人工回复、规则撤销均可停发过时结果。旧历史同秒补入不凭数据库插入顺序判为新活动，推理期间首次发现的同秒新 ID 会使快照变化并停发；发送前检查与网络提交之间仍有正常竞争窗口。

聊天请求支持图片与文件真实内容，文本任务如群总结保留原任务提示，不混入聊天人设。文件读取限制账号已授权附件、大小、提取字符、压缩条目与上下文预算；未提供内容的音视频等类型明确留为未读取。当前 OpenCode 原生传输只有文本 stdin，不能把图片 JSON 伪装成已看图，相关请求给出准确的传输限制。

QQ 基础 `face` 使用程序目录与编号，允许纯文字、独立表情和同条混排。发送前转为有序 `text/face` 段数组，同一消息不按组件拆开发送；未知编号、生成的其他 CQ 操作和 Unicode emoji 拒绝进入自动发送。原始用户消息与历史不被清洗。本轮未交付持久化多气泡批次或任务型智能体。

表情编号与名称取自项目已有固定协议资源 `static/assets/qface-BZLvZXJ8.js` 的 `QSid/QDes` 经典子集，源文件 SHA256 为 `9fee278a09655cbe79ef2e45c83487dc123b1721f1e0025fe5809edf17d80044`。预览采用同资源给出的 QFace 地址，资源失败显示明确名称；模拟协议不证明各 QQ 版本客户端的原生外观。

风格包只包含严格版本化表达枚举、受限短语、程序表情编号及可选聚合统计。账号安装索引与可分享包分开；每次生成、流式生成与修订从服务绑定账号目录读取，不依赖全局当前选择。个人包和聚合审计只存在 Git 忽略目录，不写进源码、文档、合成夹具或发布资源。公开文档仅使用虚构示例；原始聊天不进入包。

本轮还移除联系人列表中旧的个人账号优先排序特例，将目录隔离测试改为合成账号，并从旧开发记录的正文删去具体个人账号。这是当前文件的隐私清理，不重写已有 Git 历史。
