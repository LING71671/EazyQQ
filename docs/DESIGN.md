# EazyQQ 交互与视觉规范

<!-- impeccable:design-schema 1 -->

适用于 0.6.2 桌面端；规范描述当前界面及后续维护要求，不能代替接口契约。

## 界面原则

工具界面优先展示状态、有效数据和可执行操作。保持侧栏导航、主区域、抽屉的层级；空状态不添加营销文字或示例提示词。保留浅色主题与可切换的深色主题，沿用现有 Slate / Sky 配色。

| 语义 | 浅色参考 | 深色参考 |
| --- | --- | --- |
| 画布 | `slate-50` | `slate-950` |
| 主容器 | 白色 | `slate-900` |
| 边框 | `slate-200` | `slate-700` |
| 主文字 | `slate-900` | `slate-100` |
| 操作与焦点 | `sky-600` | `sky-400` |

字体采用系统无衬线栈；账号、时间和数值可使用等宽字体。图标来自 `lucide-react`，只使用有明确操作含义的图标。项目界面、CLI、脚本、文档不使用 emoji 或星光装饰；一键登录为纯文字按钮，处理时才显示加载反馈。构建和 CI 执行 `pnpm presentation:check` 防止回归。过渡应简短，遵循减少动态效果设置。

## 账号管理

登录页使用按主区域宽度响应的双栏：左侧二维码/当前会话及状态、刷新、诊断，右侧记忆账号与账号管理入口。默认 1100×740 和最小 900×600 窗口的常规三账号状态，核心操作全部首屏可见。窄内容区先显示扫码任务，再显示账号列表；多账号列表局部滚动，不推走二维码。登记和批量操作通过常驻的“账号管理与批量操作”展开，不需要翻到页面底部。目标扫码替换左侧扫码区，当前会话不被自动退出。

添加框接受逗号、空白分隔的多个 QQ 号；按钮提供登记、刷新、批量启动/登录/停止。每个账号展示身份、在线状态、当前选中标识和自启开关。

“已登记”“进程受管理”“登录已确认”“当前显示账号”是四种不同事实，不可合并成一个绿灯。选择账号后不能立即宣称登录成功。操作期间禁止重复提交，逐账号展示批量结果。

凭据过期时在目标账号扫码区显示二维码、刷新和取消。原账号状态继续显示；仅在目标身份核验成功后提交切换。取消或更换目标后，迟到的二维码和状态响应必须被丢弃。

## 健康与恢复

| 状态 | 呈现 | 操作含义 |
| --- | --- | --- |
| 正常 | 绿色与明确已验证事实 | 无需修复 |
| 未知 | 中性/等待状态，展示原因 | 扫码、显式测试或等待工作进程报告 |
| 失败 | 红色，指出具体环节 | 提供该环节可执行的恢复方式 |

不能把“模型已配置”写成“推理通过”，也不能把“端口开放”写成“WebSocket 正在收消息”。修复结果需展示 `attempted`、`ok` 和详细说明；请求成功不等于修复成功。保留原会话的操作不能呈现为已退出。

## 表单、异步与可访问性

免费模型检测沿用模型设置区域，读取目录与显式调用验证分开。先展示候选，用户启动检测后播报进度；只有本次无凭据通过才提供选用。旧模型不在目录时提示但不改配置；有额外条件、停用、目录移除和未知错误不能合并成“免费/收费”二值。记录观察时间，不使用静态免费名单。状态区使用原生 progress 与 aria-live，重复操作禁用，迟到事件按请求编号丢弃。

输入框、复选框和图标按钮必须有可理解的标签；支持键盘焦点与可见焦点环。忙碌状态禁用重复操作，状态区域使用 `role=status` 或 `aria-live`。错误区域指明失败动作，避免空错误或只显示原始对象。

账号列表轮询和登录轮询不重叠；旧响应不能覆盖新账号状态。切换后桌面重启到对应数据库与独立 WebView 目录，缓存摘要和所选群不能从其他账号继承。

## 简报与窗口

流式显示允许按 Token 或按文本段更新，不要求原生 OpenCode 强制逐 Token 返回。首段延迟和速率标注应明确计量依据。小窗口需要可滚动，操作区不能被固定导航覆盖。

最小化、最大化还原、关闭到托盘与退出应用必须遵循持久化窗口设置。健康前端被隐藏或最小化不能触发关闭沙箱或重启。

## 验收

功能修改先通过类型检查与行为测试，再检查真实渲染。账号操作测试使用独立目录和模拟协议；真实登录验收须保持用户原有会话。截图进入文档前必须人工/模型直接查看。验收事实和未完成项记录到 `docs/development/`。

## 动效策略

按钮反馈约 120ms，抽屉进入 200ms、退出 160ms，页面切换采用短透明度变化。启动数据完成即结束等待，不人为保持 900ms。正常在线、待审数量和故障颜色静态显示；只保留加载/扫码所需的循环反馈。

共享策略位于 src/styles/motion.css 与 useMotionPolicy/usePresence。窗口隐藏时暂停循环；减少动态效果时停止空间移动和循环，用静态状态与短颜色/透明度反馈保留含义。快速重开取消旧退出定时器，关闭中的抽屉立即不可交互。

## 更新流程

主程序与核心分开展示，任务互斥，进度包含下载、校验、部署或启动安装。错误可重试，未知版本不标为最新；主程序明确退出与重开，核心明确停机与配置保留边界。进度使用原生 progress 和状态播报，成功后停止旋转反馈。

登录页必须区分真实加载与失败：缺失资源、领域错误和超时显示可读原因；状态查询 15 秒与二维码等待 20 秒提示不自动登录或重启。离线恢复按钮与已就绪二维码的刷新按钮按当前状态显示。
